# atlas — метод

Лёгкий слой знаний, чтобы агент быстро понял «что, где и как работает» в проекте. Берёт у GRACE карту модулей,
grep-уникальные ID, навигацию «лог → код» и «как проверить». Отказывается от XML, разметки в коде, контрактов,
дублирующих код, и процессного слоя (spec/plan/assertions). Обоснование — `RATIONALE.md` рядом.

## 1. Принципы

- **P1 Невыводимое.** Храним только то, что агент не получит одним вызовом grep/glob/LSP/git:
  назначение и границы, процессы и режимы, пути данных и их владельцы, неимпортные связи, инварианты и их причины,
  «что менять вместе», сквозные сценарии, омонимы, как проверить.
  **Не храним:** списки экспортов и функций, импорты, перечни всех файлов, сигнатуры, историю изменений,
  пересказ шапок файлов и комментариев.
- **P2 Один факт — одно место.** Факт уровня файла — в шапке файла; «почему» конкретной строки — inline-комментарий
  со ссылкой на решение (`BACKLOG #NN`); факт уровня модуля — карточка; факт уровня системы — L0.
  Карточка не повторяет шапку, L0 не повторяет карточку.
- **P3 Доставка по каналу.** L0 грузится всем автоматически. Карточка подмешивается при чтении файла модуля —
  это страховка при правке, а не навигация. Трасса — по индексу L0, один Read.
- **P4 Бюджеты.** L0 ≤ 7.5K токенов и ≤ 150 строк; русский текст с кодом — около 2 символов на токен, то есть
  L0 ≤ 14 000 символов (`wc -m`). Карточка ≤ 6 000 символов (≈3K токенов). Трасса ≤ 15 шагов на фазу. Омонимов ≤ 15.
  Точная цена L0 — разница `usage` первого запроса свежей headless-сессии с картой и без неё.
  Бюджет — главная защита от раздувания; превышение = сигнал резать, а не расширять.
- **P5 Описательно, не нормативно.** Истина о поведении — код, о намерении — ТЗ/спека. Карточка — не контракт.
  Расхождение карточки с кодом правится в карточке.
- **P6 Свежесть по якорям** (§9), а не «были ли коммиты».
- **P7 Ноль тулчейна.** Markdown + git + Grep/Glob. Без CLI, генераторов и скриптов.
- **P8 Write-through.** Правка карточки — часть заказанного изменения кода, и только если изменился якорь,
  инвариант или связь. Отдельных «волн документирования» нет.
- **P9 Против раздувания.** Одна ловушка вошла — одна вышла. Ловушка, видимая в месте правки, — в inline-комментарий,
  не в карточку.

## 2. Раскладка и доставка

| Файл | Уровень | Как попадает к агенту |
|---|---|---|
| `AGENTS.md` | L0 | `@AGENTS.md` в CLAUDE.md → при старте сессии и после `/compact`; Codex читает AGENTS.md сам |
| `.claude/rules/atlas/M-<ID>.md` | L1 — карточки | правило с `paths:` → подмешивается при Read совпавшего файла |
| `docs/atlas/F-<ID>.md` | L1 — трассы | по индексу L0, один Read |
| `.claude/agents/atlas-scout.md` | поиск | кастомный субагент: получает CLAUDE.md → AGENTS.md и правила |
| шапки файлов, inline-комментарии | L2 | обычное чтение кода |

Механика Claude Code, на которую опирается раскладка (проверено по докам, 2.1.28x):
- AGENTS.md читается сам, только если в проекте нет CLAUDE.md. Иначе нужен `@AGENTS.md` в CLAUDE.md
  (импорт раскрывается при старте, до 4 уровней вложенности; внутри `` `...` `` не раскрывается).
- Правило без `paths` грузится при старте всегда. Правило с `paths` — при **Read** подходящего файла;
  Grep/Glob/Write его не вызывают. После `/compact` — снова при следующем Read.
- Встроенные Explore и Plan пропускают CLAUDE.md и правила. Кастомные субагенты получают их, если в определении
  нет `omitClaudeMd`. Отсюда atlas-scout.
- Во frontmatter правила читается только `paths` (YAML-список или строка через запятую); остальные поля
  игнорируются — туда кладём `synced`. **Невалидный frontmatter ⇒ правило грузится как безусловное, в каждую сессию.**

## 4. Карточка модуля

### 4.1 Нарезка
- Модуль — вертикальный срез по смыслу (подсистема, фича), а не папка и не файл. Средний проект — 10–20 модулей.
- ID: `M-<UPPER-KEBAB>` по смыслу (`M-PEER-MAIL`), не по пути.
- Каждый свой файл — ровно у одного владельца. Файлы, которые меняются почти в каждом коммите вместе с разными
  модулями (общие типы, i18n, крупные реестры), — в L0 «Общие файлы», без владельца.
- Горизонтальный контракт (например, HTTP-API фронт ↔ бэк), который правят вместе со многими модулями, —
  отдельная небольшая карточка «как добавить X».
- Границы проверять по реальным импортам и совместным коммитам (`git log --name-only`), а не по папкам.

### 4.2 Frontmatter
```yaml
---
paths:
  - 'server/utils/agents/peer.ts'
  - 'server/utils/agents/{peer-runner,inbox-watcher}.ts'
  - 'app/components/agents/AgentMail*.vue'
synced: 1a2b3c4
---
```
- Globs — в одинарных кавычках, от корня проекта; правила — §7.
- `synced` — короткий SHA коммита, до которого карточка просмотрена (§9). Загрузчик поле игнорирует.

### 4.3 Разделы — порядок под правку
1. `# M-<ID> — <название>` и одна строка сути, только если её нет в L0.
2. **Инварианты и грабли** — правило → причина (`BACKLOG #NN`, инцидент, дата решения).
3. **Что ещё менять вместе** — «меняешь X → поправь Y, Z» (файлы, тексты для модели, доки).
4. **Состояние и побочки** — что пишет и читает на диске, какие процессы порождает, сеть, env.
5. **Неимпортные связи** — через регекс путей, заголовок, общий файл/том, событие, long-poll, текст для модели.
6. **Проверка** — регрессионный набор тест-кейсов, наблюдаемые сигналы (поле, строка лога), команда сборки.
7. **Точки входа** — 2–6 якорей `файл:Символ` с ролью.
8. **Не здесь** — смежное → `M-<ID>`.

Пустой раздел не пишется. Типичный размер — 12–50 строк.

### 4.4 Что не писать
Список файлов модуля (он в `paths`, а назначения — в шапках: `rg -m3 '^\s*//' <globs>`); экспорты и сигнатуры;
пересказ шапок и комментариев; историю правок; планы и открытые задачи (они в BACKLOG); сведения, которые
видны в месте правки (их место — inline-комментарий).

### 4.5 Шаблон
```markdown
---
paths:
  - '<glob>'
synced: <sha7>
---
# M-<ID> — <Название>

**Инварианты и грабли**
- <правило> — <причина> (BACKLOG #NN)

**Что ещё менять вместе**
- <изменение> → <что ещё>

**Состояние и побочки**
- <путь/ресурс>: <пишет/читает, когда>

**Неимпортные связи**
- <сторона А> ↔ <сторона Б>: <через что>

**Проверка**
- <T-кейсы> · <сигналы> · <команда сборки>

**Точки входа**
- `<файл>:<Символ>` — <роль>

**Не здесь**
- <смежное> → M-<ID>
```

## 5. Трасса сценария

Одна трасса — один файл `docs/atlas/F-<ID>.md`, ≈1.5–2K токенов.

- Строка «Процессы» с тегами: например `[B]` браузер · `[H]` хаб · `[A]` agent-host · `[C]` claude.
- Шаг: `N. [тег] путь:Символ[#«раздел»] — что происходит (условия, коды ответов, куда пишет)`.
- `⟿` — асинхронный переход (фон, очередь, long-poll).
- Больше 15 шагов → фазы с заголовками (`## Отправка`, `## Доставка`, `## Ответ`).
- Общая часть с другой трассой — ссылкой («шаги 10–13 из F-TURN»), не повтором.
- Якорь внутрь длинной функции — `#«раздел»` по существующему разделителю вида `// ---- раздел ----`.
  Разделитель добавляется только при касании функции и только если на него нужен шаг.
- Хвост трассы: **Состояние** (переходы статусов), **Сбои** (коды, тексты ошибок), **Логи** (где и какие строки),
  **Варианты режима** (чем отличаются другие режимы запуска), **Проверка** (тест-кейсы).

Шаблон:
```markdown
# F-<ID> — <сценарий>
Процессы: [X] … · [Y] …
Триггер: …

## <Фаза>
1. [X] `путь:Символ` — …
2. [Y] `путь:Символ` — … ⟿ …

Состояние: …
Сбои: …
Логи: …
Варианты режима: …
Проверка: …
```

Новая трасса заводится, когда реальный вопрос «как работает» потребовал ≥ 5 вызовов, чтобы проследить путь.

## 5a. Разбор изменений — распределённо, без отдельного файла
Замер 24.09 показал: на «что затронет» и планах агент со слоем принимает рецепт или указатель карточки за полный
список и закрывает анализ раньше агента без слоя. Лечится не новым файлом, а тем, что каждая часть знания живёт
там, где агент её уже получает:
1. **Порядок разбора — в протоколе L0 (п. 3):** grep изменяемой сущности по всему репозиторию без маски → таблица
   потребителей «меняется / нет — почему» → вердикт по каждой поверхности и термину из вопроса → тело механизма и
   причина решения (`BACKLOG #NN`) → образец (`git log -S…`, `git log --grep '#NN'`, `git show --stat <sha>`), сверить
   набор файлов с доками и тестами → разделы L0 как чек-лист. Рецепт и «Что ещё менять вместе» — нижняя граница.
2. **Чек-лист последствий — сами разделы L0:** «Процессы и режимы» (кто исполняет путь в каждом режиме), «Карта
   данных» с колонкой «До существующих» (когда изменение доходит до уже созданных экземпляров: при старте / при
   создании / при следующем действии / после пересборки образа / никогда), «Сквозные правила» (где задаётся значение
   на dev/prod и как попадает в контейнер; канал текстов для модели; совместимость при неодновременном обновлении),
   «Общие файлы» (контракт клиента, i18n), «Документы» (строка BACKLOG + T-кейс + раздел ТЗ).
3. **Рецепты — только в карточке-владельце**, раздел «Что ещё менять вместе»: «<вид изменения> <артефакт>: минимум …;
   условия — вопросы (…?); образец `<sha>`». Вид — новое / изменение значения или умолчания / удаление, откат.
   Образцы — только реальные совместные коммиты (`git log --name-only`). В L0 — индекс «вид → карточка».
4. **Грабли и план:** по каждому затронутому модулю пройти «Инварианты и грабли» его карточки и назвать задетые; план =
   правка · раскатка (раздел L0 «Раскатка в docker»: деплой хаба / пересборка aiui-agent и пересоздание контейнеров /
   пересоздание контейнера / новый процесс сессии / никогда) · совместимость с уже существующими данными · проверка · документы.

## 6. Омонимы
Только слова, которые grep не различает по смыслу: одно слово — несколько сущностей в коде
(«сессия»: запись хаба / сессия движка / cookie-сессия). Формат строки: `слово — смысл₁ → где; смысл₂ → где`.
Каждый смысл ссылается на идентификатор кода — иначе строка не проверяема и сгниёт.

## 7. Globs в `paths`
Семантика — как у `.gitignore` (проверено на Claude Code 2.1.281 по транскриптам сессий):
- Шаблон **со** `/` внутри (`'server/utils/agents/peer.ts'`, `'app/pages/agents/**'`) — от корня проекта.
- Шаблон **без** `/` (`'Dockerfile'`, `'package.json'`) матчит файл с таким именем **на любой глубине** —
  в том числе в `node_modules/**` и чужих клонах; это же верно для альтернатив внутри `{…}`.
- Корневой файл — только с ведущим `/`: `'/Dockerfile'`, `'/{package.json,nuxt.config.ts,.env.example}'`.
- В одинарных кавычках. Двойные кавычки + `\` = ошибка YAML ⇒ правило станет безусловным.
- Скобки `[...]` — класс символов glob, а не буквальное имя: `server/api/agents/[...path].ts` **не** матчит
  сам файл. Для файловых маршрутов Nuxt/Next брать каталог: `'server/api/agents/**'`.
- Фигурные скобки — перечисление: `'app/composables/{useAgentChat,useAgentSessionChat}.ts'`.
- Отрицаний нет. Пересечение globs двух карточек разрешается при `atlas-sync`: файл отдаётся карточке с более
  точным glob, у второй glob сужается.

## 8. Протокол агента (дословно в L0)
1. Модуль — по таблице «Модули» или «Омонимы»; входные файлы — сразу в Read, без обхода каталогов.
2. «Как работает X» — сначала трасса из «Трассы» (один файл); она же — для изменения, задевающего шаг трассы.
2a. «Что затронет X» или план изменения — порядок разбора §5a п.1, затем разделы L0 чек-листом; рецепты и
   «Что ещё менять вместе» карточек — нижняя граница, а не готовый ответ.
3. Карточка модуля подмешивается сама при Read его файла: инварианты, «что ещё менять», побочки, проверка.
4. Поиск — субагентом `atlas-scout`. Если всё же Explore/Plan — вставь в промпт нужные строки «Модули» и пути
   карточек/трасс: встроенные агенты не видят CLAUDE.md.
5. Ответ — со ссылками `путь:символ`, проверенными в этой сессии; текущее поведение отделяй от планов в документах;
   неуверенность — назови и укажи следующий поиск. Карта говорит, где смотреть, но ничего не доказывает.
6. Изменил поведение, побочки, инвариант или связь модуля — обнови его карточку (и трассу) в том же изменении,
   `synced` — на новый HEAD.
7. Не читай «Не читать».
8. Параллельные правки: модуль — единица write-scope; общие файлы правит один исполнитель.

## 9. Свежесть
Карточка устарела, только если с `synced`:
- (а) в её globs появился, исчез или переименован файл;
- (б) diff задел строку с идентификатором, который карточка цитирует (символ, маршрут, env, ключ хранилища,
  фрагмент лога, T-кейс);
- (в) diff добавил или убрал export, маршрут, env-переменную или путь данных.

Иначе `synced` сдвигается на HEAD без правки текста («просмотрено до»). `git diff <synced>..HEAD -U0 -- <globs>`
даёт всё нужное; незатронутые модули не читаются.

## 10. Проверки C1–C6 (агентом, Grep/Glob/git)
- **C1** Каждый glob каждой карточки матчит ≥ 1 файл. Инструмент Glob ведущий `/` не принимает, а шаблон без `/`
  матчит на любой глубине: корневые шаблоны проверять без `/` и смотреть, что найден именно корневой файл;
  пути со скобками `[...]` — через Read.
- **C2** Каждый свой исходник — ровно у одного владельца или в «Общих файлах»; вендор и «Не читать» исключены.
  Способ: Glob по всем карточкам → объединение → сравнить с Glob своих каталогов; вывести «без владельца» и «два владельца».
- **C3** Каждый путь репозитория в `` `…` `` из L0, карточек и трасс существует (Glob; со скобками — Read).
  Пути времени выполнения (`<dataDir>/…`, `/agent/…`), пути в клонах агентов и маршруты API не проверяются —
  пиши их без обратных кавычек или с явным префиксом (DATA/…).
- **C4** Каждый якорь `путь:Символ` находится в файле (Grep символа в пути); `#«раздел»` — Grep текста разделителя.
- **C5** Бюджеты (§1 P4) и валидный frontmatter: первая строка `---`, `paths:` — список строк в одинарных кавычках,
  закрывающая `---`, `synced` — 7+ hex-символов.
- **C6** Устаревшие карточки по §9.

Отчёт проверок — таблица: проверка · нарушений · примеры (до 5) · что сделать.

## 11. Анти-паттерны
- Зеркало кода: списки функций, экспортов, полей типов. Устаревает первым, выводится одним grep.
- Пересказ ТЗ. ТЗ — намерение; в карту — только ссылка и граница «ТЗ ↔ код».
- «Полнота»: карточка на каждый файл, трасса на каждый сценарий. Карта полезна, пока она короткая.
- Ссылки без якоря («см. код хаба»). Каждая ссылка — `путь:символ`, иначе C4 не поймает гниение.
- Вечные ловушки. Если ловушку закрыли кодом — удалить из карточки.
- Изобретённые ID для того, у чего ID уже есть: решения — `BACKLOG #NN`, проверки — T-кейсы.
- Указатель, похожий на исчерпывающий: «правь раздел X файла Y» вместо «файл Y, искать grep `…`»; грабли без места
  правки по образцу — агент переносит правку туда, где проявляется симптом.
- Рецепт по слову: закрытый список в L0 («переменная = A + B») агент подбирает по совпадению слова и на нём
  останавливается. Рецепты — только в карточке-владельце, ключ — вид изменения, условия — вопросы, с образцом-коммитом.
