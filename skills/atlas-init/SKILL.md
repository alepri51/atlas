# atlas-init

Перед началом прочитай целиком `../../references/atlas-method.md` — там форматы, бюджеты и проверки.
Обоснование решений — `../../references/RATIONALE.md`.

## Когда
- Карты atlas в проекте нет, или владелец велел построить её заново.
- Карта уже есть → не этот скилл, а `atlas-sync`.

## Политика моделей
- Сбор фактов (инвентаризация, счётчики, `git log`, списки файлов) — Sonnet-разведчики.
- Нарезка модулей, карточки, трассы, L0 — основная модель: сам или субагенты **без** model-override.

## Шаги

### 0. Предпроверка
- Прочитать CLAUDE.md, README, оглавление `docs/`.
- Найти существующие слои: `.grace/`, `docs/*.xml` (GRACE 3 / codescribe), AGENTS.md. Если есть — сообщить и спросить
  через AskUserQuestion, строить ли atlas рядом (старый слой не трогать).
- Черновик «Не читать»: вендорный UI-кит, сгенерированное, lock-файлы, бандлы плагинов, чужие клоны.
- `git status`: незакоммиченные правки владельца не трогать.

### 1. Инвентаризация — 3–5 разведчиков параллельно, по областям
Каждый возвращает факты с путями, без оценок:
- шапки файлов (первые строки комментариев) по каталогам;
- точки входа: маршруты API, страницы, обработчики, CLI, фоновые циклы, воркеры;
- процессы и режимы: Dockerfile, compose, скрипты package.json, env-переключатели режимов;
- пути данных: что пишется на диск / в БД / хранилище, кем пишется и кем читается;
- env-переменные: где читаются, что значат;
- логи: куда пишутся, формат, ротация; типичные строки;
- тексты для модели: промпты, описания инструментов, форматы сообщений, файлы правил для агентов;
- совместные изменения: `git log --name-only` за 2–4 недели → пары файлов, чаще всего меняющихся вместе,
  и самые «горячие» файлы;
- ссылки на решения в коде (`BACKLOG #NN`, `#NNN`, даты решений) и где решения записаны.

### 2. Нарезка модулей → гейт одобрения
- Таблица `ID · суть · globs · процесс · ≈файлов/строк`, плюс «Общие файлы» и «Не читать». Правила — метод §4.1, §7.
- До гейта прогнать C1 и C2: каждый glob матчит файлы; каждый свой файл — ровно у одного владельца.
- **Гейт:** показать таблицу и список трасс (5–6 важнейших сценариев) через AskUserQuestion — принять / слить /
  разделить / правки. Без одобрения дальше не идти.

### 3. Карточки
- Параллельные субагенты основной модели, каждому — непересекающийся набор модулей.
- Вход субагенту: метод §4 и §7, строки его модулей с globs, факты инвентаризации по его области, шаблон §4.5.
- Требования: каждое утверждение — из прочитанного кода или документа; каждый якорь `файл:Символ` проверен Grep;
  ≤ 6 000 символов; `synced` — текущий HEAD; не повторять шапки файлов и inline-комментарии.

### 4. Трассы
- Одобренные сценарии, по файлу `docs/atlas/F-<ID>.md` (метод §5). Каждый шаг прослежен по коду, якоря проверены Grep.
- Параллельно — субагенты основной модели, по трассе на субагента.

### 5. L0 — `AGENTS.md`
По шаблону метода §3: ≤ 150 строк и ≤ 14 000 символов (P4). Протокол — метод §8 дословно.
Цену проверить: `usage` первого запроса свежей headless-сессии с картой минус без неё.

### 6. Отчёт «документы ↔ код»
Расхождения ТЗ, README и доков с кодом, найденные по ходу, — списком в чат с доказательствами. Доки не править.

### 7. Проверки C1–C6 (метод §10) → исправить нарушения.

### 8. Подключение — только в пределах одобренного владельцем
- `CLAUDE.md`: строка `@AGENTS.md`; строка «Поиск по коду — субагентом atlas-scout (Sonnet): встроенные Explore/Plan
  не получают CLAUDE.md и карту проекта.»
- `.claude/agents/atlas-scout.md` — если его нет, скопировать шаблон `../../templates/atlas-scout.md`.

### 9. Проверка доставки
Свежая headless-сессия в каталоге проекта (`claude -p … --agent atlas-scout --output-format stream-json`):
- L0 в контексте без чтения файлов (вопрос: «процитируй заголовок AGENTS.md, не открывая файлов»);
- после Read файла модуля его карточка в контексте, а на постороннем Read — нет;
- ни одно правило atlas не грузится безусловно (признак битого frontmatter).

### 10. Итоговый отчёт
Модули, трассы, размеры (строки и символы), результаты C1–C6, проверка доставки, открытые вопросы.

## Границы
Исходный код не меняется. Старые слои документации не удаляются. Коммиты — только по команде владельца.
